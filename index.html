Architecture

Network-Based Document Processing

Pipestream AI operates as a network graph, not a linear pipeline. The Pipeline Engine acts as the central routing hub, orchestrating data flow between processing nodes. Documents can enter through multiple entry points and be routed through various processing paths based on configuration.

Multiple Entry Points

Connectors, direct API calls, or Kafka events

Flexible Storage

S3 repository or in-memory processing

Transport Options

gRPC for low latency, Kafka for high throughput

Dynamic Routing

Runtime routing decisions based on configuration

Processing Flow

Documents flow through four main stages: Data Loading (ingestion), Data Transformation (parsing to text), Data Enhancement (chunking, embeddings, AI processing), and Sink (indexing to search engine).

Core Services

Connectors

Discover, authenticate, and stream documents from various sources

Repository Service

Manages S3 storage and metadata, publishes events

Pipeline Engine

Orchestrates routing and transport between modules

Processing Modules

Parsers, chunkers, embedders, and specialized processors
