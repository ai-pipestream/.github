Protocol Buffers at Runtime.
A Schema Registry on Git.

ProtoMolt is a modular Java toolkit that loads, validates, reshapes, indexes, and serves protobuf messages from descriptors, not generated classes — and a schema registry that stores every version as a Git commit while speaking the Confluent protocol your serializers already use.

What It Does

Forty-two focused modules under one BOM. Use one, or use the whole loop: gather → validate → register → serve → index.

🧬

Descriptor-Native Core

Every code path works on Descriptor / FileDescriptor. A DynamicMessage resolved from a registry at runtime behaves exactly like a compiled-in type, so no module is coupled to any generated class.

📥

Gather from Anywhere

Filesystem trees, jars on the classpath, Git repositories (monorepo layouts, auth, clone caching), Maven coordinates, Confluent and Apicurio registries. Text sources compile to descriptors at runtime, no protoc required.

🗄️

A Registry That Is a Git Repo

One commit per schema registration. History, review, branching, and disaster recovery are just Git, while clients see the Confluent subjects API and gRPC consumers fetch compiled binary descriptor sets directly.

🧯

Compatibility-Gated Writes

A typed diff engine with 35 named rules classifies every change by wire, JSON, and source impact, evaluated under backward / forward / full modes and their transitive variants. Breaking registrations are rejected with the exact rule, path, and version.

✅

Validation on the Schema

Rules travel as descriptor options, so validation follows the schema everywhere. The protovalidate dialect passes the complete conformance suite — 2,872 of 2,872 cases, re-scored by buf’s own runner in CI on every push.

📤

Publish to Existing Registries

Confluent and Apicurio publishers with reverse-topological reference registration, idempotent re-publish, and dry runs. Federate: keep Git as the source of truth and mirror subjects to the registries your Kafka estate already runs.

🔎

Search Indexing Hints

A descriptor-option standard for how fields come to rest in an index: text vs keyword, analyzers, numeric and date ranges, kNN vector parameters, map policies. Generators emit Lucene, OpenSearch, and Solr schemas from the same hints.

🔀

Mapping, Metadata, CEL

Text mapping rules for reshaping messages, CEL filters and selectors where expressions matter, and a metadata standard for extracting declared facts from any type at runtime.

🌐

JSON Kept at the Edge

A framework-agnostic REST gateway with JSON transcoding, OpenAPI 3, and JSON Schema generation, hosted on any of six servers (JDK, Vert.x, Netty, Spring, Micronaut, Quarkus). Inside the toolkit, everything stays binary.

Concrete Examples

The same four steps a team actually takes, in the order they take them.

1 — Gather protos from a Git repo and compile them at runtime

ProtoGatherer gatherer = GitProtoGatherer.builder()
        .repo("https://github.com/acme/schemas.git")
        .ref("main")
        .subdir("proto")
        .build();

CompiledProtos compiled = ProtoSourceCompiler.compile(gatherer.gather());
DescriptorRegistry registry = DescriptorRegistry.create();
registry.addLoader(new GatheringDescriptorLoader(gatherer));

2 — Run a schema registry over a bare Git repository

var store  = GitSchemaRegistryStore.open(Path.of("/srv/schemas.git"));
var server = new SchemaRegistryServer(config, store,
        ActionCatalog.defaults(ActionContext.create()));
server.start();

Any Confluent-compatible client now works against it, and every registration is a commit:

curl -s -X POST localhost:8081/subjects/orders-value/versions \
     -H 'Content-Type: application/vnd.schemaregistry.v1+json' \
     -d @order.json
# gRPC consumers skip JSON entirely:
curl -s localhost:8081/protomolt/subjects/orders-value/descriptor-set -o orders.dsc

3 — Gate a change before it ships

var checker = CompatibilityChecker.builder().build();
var result  = checker.check(oldSources, newSources, CompatibilityMode.BACKWARD);

// A removed field surfaces as a typed change, not a diff hunk:
// FIELD_REMOVED at orders.Order.discount_code
//   impacts: [WIRE_BACKWARD, JSON_BACKWARD]

The registry runs the same engine on every write, so what passes locally registers cleanly.

4 — Depend on it

dependencies {
    implementation platform('ai.pipestream:protomolt-bom:<version>')
    implementation 'ai.pipestream:protomolt-registry-server'
    implementation 'ai.pipestream:protomolt-compat'
}

One BOM aligns all forty-two modules. Pick the two you need today; the rest are there when you need them.

Meta for Meta: the gRPC Service of Itself

gRPC is defined in protobuf. So is ProtoMolt’s future API surface.

🧰 Today: a self-describing verb catalog

Every operation — compile, validate, diff, check compatibility, render schemas, evaluate CEL — is already a named action with a machine-readable input schema, mounted on the registry server. Consoles and LLM tools drive the entire toolkit through ten verbs, and every result is machine-verified: compiled, compatibility-gated, conformance-tested.

🌀 Next: the same verbs as a gRPC service

The action envelopes become protobuf messages and the catalog becomes a gRPC service — defined in .proto, registered in the registry it runs on, serving its own descriptor set. Point any language’s protoc at the registry and you have a native client for the system that governs your protos. The tool that manages the format is spoken in the format.
